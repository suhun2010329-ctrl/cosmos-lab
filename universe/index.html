팽창이 곧 시계

시간 대신 우주의 크기(척도 인자 a)로 시계를 돌립니다. 우주가 10배 커지는 일이 한 칸이라, 빅뱅 후 3분의 원소 합성과 최근 수십억 년이 비슷한 길이를 차지합니다. ‘보통 시계’로 바꾸면 처음 38만 년이 첫 프레임 안에 지나가 버립니다.

배경 우주와 빛

프리드만 방정식을 Planck 2018 값(H₀ = 67.36, Ω_b h² = 0.02237, Ω_c h² = 0.1200, T_CMB = 2.7255 K, N_eff = 3.046)으로 풀고, 초기 우주 온도는 유효 자유도 g*(T)로 보정합니다. 원소 합성은 중성자↔양성자 반응률로 n/p를 적분하고, 재결합은 RECFAST식 피블스 방정식으로 xₑ(z)를 풀어 마지막 산란면과 플라스마 안개 두께를 계산합니다.

은하 · 별 · 행성

N-body로 키운 32,768개 입자에 관측된 은하 별질량 함수(Baldry 2012)만큼의 은하(별 질량 10⁸ M☉ 이상, 약 11만 개)를 붙입니다. 무거운 은하일수록 빽빽한 곳에 놓이고, 크기(van der Wel 2014)·별 형성 정지(Peng 2010)·질량 성장(Madau–Dickinson 2014)이 시간에 따라 바뀝니다. 가까이 가면 은하 하나가 수만 개의 별로 절차 생성되고, 그 안의 별은 Kroupa 초기 질량 함수로, 행성은 케플러 관측 통계와 금속량 의존성(Fischer & Valenti 2005)으로 만듭니다.

원소의 기원

각 원소를 만드는 천체(빅뱅, 무거운 별의 폭발, 가벼운 별의 죽음, 백색왜성 폭발, 중성자별 충돌, 우주선)의 비율은 Johnson(2019) 주기율표를 단순화했습니다. 각 천체가 원소를 내놓는 시점은 별 형성 역사에 지연 시간 분포(∝ t⁻¹, Maoz & Mannucci 2012)를 곱해 계산하고, 존재비는 Asplund 외(2009) 태양 값을 씁니다.

게임 엔진식 최적화

  • LOD 4단계: 우주망 점 → 은하 임포스터(가짜 그림) → 별 수만 개짜리 절차 생성 은하 → 별계 장면. 오픈 월드 게임의 거리별 모델 교체와 같고, 단계 사이는 교차 페이드로 바꿔 튀지 않게 합니다.
  • GPU 인스턴싱: 은하 11만 개를 그리기 호출 한 번으로 그립니다(숲·군중 렌더링 방식).
  • 정점 애니메이션 텍스처(VAT): N-body 결과를 텍스처 키프레임 두 장에 담고 정점 셰이더에서 보간합니다. CPU는 키프레임이 바뀔 때만 1 MB를 올리고, 텍스처 두 장을 번갈아 씁니다(더블 버퍼).
  • 부동 원점: 카메라를 항상 원점에 두고 세상을 옮겨, 148 Mpc 상자에서 수백 파섹짜리 별 무리까지 float 정밀도 문제 없이 확대합니다(Kerbal Space Program 방식). 별계는 별을 원점으로 한 별도 장면으로 불러옵니다.
  • 주기 경계 최소 이미지: 상자 안에서는 셰이더가 모든 은하를 카메라에 가장 가까운 복제 위치로 옮겨, 끝없이 이어진 우주처럼 보입니다.
  • 절차 생성 + 씨앗: 은하 모양과 별계는 저장하지 않고 은하 번호에서 결정적으로 다시 만듭니다(No Man's Sky, Elite Dangerous 방식).
  • 객체 풀링 · 시간 분할: 정밀 은하 3개분 버퍼를 미리 만들어 재사용하고, 별 생성은 한 프레임에 몇 밀리초씩만 나눠 합니다.
  • 공간 해시 격자: 카메라 주변 은하만 빠르게 찾아 정밀 LOD 후보를 고릅니다.
  • 화면 크기 컬링: 화면에서 너무 작고 어두운 은하는 정점 셰이더에서 버립니다.
  • 자동 노출(눈 적응)와 동적 해상도: 가까이 갈수록 노출을 낮추고, 프레임 시간이 길어지면 렌더 해상도를 낮춰 속도를 지킵니다. N-body는 웹 워커(별도 스레드)에서 돌립니다.

한계

은하 위치는 관측된 우주 지도(SDSS·DESI)와 같은 통계에서 나온 것이지, 실제 은하 하나하나를 재현한 지도는 아닙니다. N-body 입자 하나가 우리 은하 헤일로 정도의 질량이라, 작은 은하는 부분격자 모형으로 배치합니다. 행성은 실제 발견된 외계행성이 아니라 관측 통계를 따르는 가상의 행성입니다. 행성과 별의 화면 크기는 보기 쉽게 확대했습니다.
